Property holds

The method, per the local formal-verification discipline: draw the statechart first, pick the one riskiest property, and use the tool that fits it. For the Buyback, the riskiest property is the money math — the failure class that the same week's falsification passes kept finding elsewhere: counts that didn't reconcile with their own receipts.

The property: stake is never created or destroyed silently — for any sequence of records and re-judgments, total burned never exceeds total staked; each decision's burn is all-or-nothing (0 or its full stake); and surviving stake always equals staked minus burned, exactly — globally and per schema.

The tool was Verus, because the property has to hold for all inputs — arbitrary ledger lengths, schema ids, stakes, flip patterns — not up to a test bound. The ledger was encoded integer-only, no floats. Verdict on the honest implementation: 25 verified, 0 errors. Then the teeth test: an identical copy with one line changed, so a flip burns only half the stake and quietly credits the rest back. The prover refused it — postcondition not satisfied, 24 verified, 1 error. A proof that can't reject the broken version isn't evidence; this one can and did. The rerun suite requires both outcomes, and it passes.

The honest gaps

The proof covers a reference implementation written for this run — not the pilot's ad-hoc computation, and no conformance replay has yet checked the two against each other. The seat thresholds the ledger enforces are policy, not theorem: what's proven is that the tallies reconcile, not that the thresholds are wise. And coverage is out of scope by construction — a decision that never reaches the ledger is invisible to the proof. The next run's target is already named: the decision engine's own Rust core.
